# Reproducible host experiments

These scripts execute real local programs. Correctness fixtures are not hardware
performance experiments. No script generates placeholder results.

## Quick start

Requires Python 3.8+, CMake and a C++17 compiler. Run from the repository root:

```sh
python3 scripts/run_experiments.py all --list
./scripts/experiments/run_all.sh --repeat 1 --jobs 2
# Independent run, retaining a separate build configuration:
./scripts/experiments/run_all.sh --sanitize --build-type Debug
```

Each case has its own shell entry point and can be repeated with `--repeat N`.
All entry points accept `--output NEW_DIRECTORY`, `--build-dir DIRECTORY`,
`--timeout SECONDS`, and `--build-timeout SECONDS`. Existing result directories
are rejected rather than overwritten. Do not concurrently share a build directory;
use distinct `--build-dir` values for parallel invocations.

| Case | Entry point | What is exercised |
|---|---|---|
| `admission` | `scripts/experiments/run_admission.sh` | Admission, accounting and placement invariants |
| `scheduler` | `scripts/experiments/run_scheduler.sh` | Weighted service, fairness and admission retries |
| `lifecycle` | `scripts/experiments/run_lifecycle.sh` | Producer completion and final release ordering |
| `consumers` | `scripts/experiments/run_consumers.sh` | Registered multi-reader lifecycle and replay |
| `shared-memory` | `scripts/experiments/run_shared_memory.sh` | Shared device capacity across tenants |
| `adapter-contract` | `scripts/experiments/run_adapter_contract.sh` | Split/merge and frontend adapter contracts |
| `adapter-demo` | `scripts/experiments/run_adapter_demo.sh` | Filter/group execution with spill and reload |
| `recovery` | `scripts/experiments/run_recovery.sh` | Checkpoint restore and release replay |
| `recovery-bench` | `scripts/experiments/run_recovery_bench.sh` | Host reconstruction/replay timings; excludes checkpoint I/O |

## Recorded evidence

Every run writes a fresh UTC-stamped directory under `experiment-results/`:

- `metadata.json`: Git revision and pre-run worktree status, host, compiler,
  CMake version, build configuration, selected cases, repetitions and final status.
- `CMakeCache.txt`: resolved build configuration.
- `commands.json`: exact commands, return codes and elapsed wall times.
- `configure.log`, `build.log`, and one raw log per case/repetition.
- `runs.csv`: successfully completed cases and **harness** wall time.

A build failure, missing executable, timeout or nonzero test exit fails the run;
completed logs and failure metadata remain available. There is no empty CTest
selection that can silently pass. Harness duration includes process startup and
is not operator latency, query throughput, fairness, or a DPU speedup measurement.
Repeated correctness checks do not constitute independent workload samples.

## Scope and remaining experiments

The recovery microbenchmark is the only timing benchmark in this suite. It
reports restore/replay median and p99 over 100 trials after 10 warmups for
1, 64, 256 and 1024 allocations. It excludes checkpoint I/O and process startup.
For validated per-run CSV and a median-across-runs summary, first build it, then:

```sh
./scripts/experiments/run_recovery_bench.sh
python3 scripts/run_recovery_bench.py   build/experiments-Release/tide-recovery-bench   experiment-results/recovery-five-runs --runs 5
```

The summary aggregates per-run quantiles; its p99 column is not a pooled p99.
Raw output is preserved even when a later repetition fails. NaN/negative timings,
incomplete allocation sweeps, duplicate sizes and invalid trial counts are rejected.

End-to-end SSB/TPC-H throughput, multi-tenant tail latency, placement ablations and
DPU hardware sweeps require a deployed engine, workload generator, pinned input
snapshot and hardware inventory. They are not implemented by these control-library
fixtures. Historical `data/` files are not regenerated by the runner.
